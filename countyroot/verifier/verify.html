Verify a parcel

Checks one parcel against the county's fingerprint on Solana, in your browser.

Not a deed. Not a title. Not a token. A match means this parcel row is in the county extract CountyRoot fingerprinted. The county remains the legal source.

How this works

  1. Your browser downloads a few small proof files for this county (about 100 KB or less each), not the whole parcel list.
  2. If the exact ID isn't in the county file, it tries the same ID without case, spaces, dashes, dots or leading zeros, then any lookup aliases the county has (for example Travis's TCAD Property ID). It always tells you which parcel ID it matched. Aliases only help find the parcel ID; they are not part of the fingerprint.
  3. It recomputes the parcel's fingerprint (leaf) from the exact row: a domain-separated SHA-256 (countyroot/leaf/v2) over the county FIPS code, the exact parcel ID, its repeat number (for an ID listed more than once) and the areas as whole numbers (micro-acres and hundredths of a square foot), so no rounding or text formatting is involved. Older epochs published before leaf format 2 use the v1 leaf sha256(parcel_id|acres|lot_sqft); the page uses whichever format that epoch's proof files declare.
  4. It hashes that leaf up the Merkle tree (leaves sorted by parcel ID) to a root that also binds the county, epoch and parcel count, using the neighbouring fingerprints from the proof files. For an ID that isn't in the file, the two neighbouring rows prove it is absent.
  5. It reads the county's head account and root accounts from Solana Devnet (finalized), checks they are CountyRoot's and for this county and epoch, and compares the computed root. The head says which epoch is current. An active epoch is the county's current data; a superseded epoch is still a valid record of an earlier release; a retracted epoch must not be relied on, even when a row matches.
  6. It shows where the data came from, as recorded on-chain: when the county file was fetched (“no later than” when only an upper bound is known), the county's own data date, and the hashes of the packet and the build manifest. “Check the manifest” downloads that epoch's manifest and confirms its hash and contents match the chain.

The proof files are not trusted: if any byte in them is wrong, the computed root won't match. If Solana can't be reached, the page compares with the fingerprint published on this site instead and tells you so; open the Explorer link to confirm it yourself. For a check that doesn't rely on this website, use the CountyRoot SDK's countyroot verify with the full parcel list.
